# 北斗短剧素材推荐助手（BeidouReco）

Windows 桌面工具：填入你自己的**北斗矩阵发布 API Key**，一键拉取发布组、素材库、出单、剧目广场数据，
生成两类可直接复制/导出的成稿：

1. **按发布组推荐剧目** —— 综合每日剧单、YC 一周新剧、分销推广剧单、每日必做&推荐剧单、
   运营短剧看板、短剧上新监控面板、类型判定规则，覆盖全部剧场与分组，无遗漏、不重复；
   按**素材紧张度（剩余集数 ÷ 主页数）降序**输出，优先级规则：每日剧单排名高（关注备注）＞
   看板前一日出单多 ＞ 个人出单多的剧。
2. **剧名定组表** —— 输入一批剧名，逐部生成：剧目、上线、类型、题材、剧场、推广、推荐理由、优先级。

## 下载

到 [Releases](../../releases) 下载 `BeidouReco.exe`（单文件，免安装，双击即用）。
首次启动会自动打开浏览器访问 `http://127.0.0.1:18765/`（本机回环，数据不出本机）。

## 使用

1. 首次打开点击右上角「设置 API Key」，粘贴你的北斗 API Key（`bd_` 开头），点「测试连接」后保存。
   Key 只保存在本机 `%APPDATA%\BeidouReco\config.json`。
2. 点「拉取 / 刷新数据」：拉取发布组、9 库素材库存、出单（按剧聚合）、8 个剧场广场、
   运营看板、上新监控面板（全程约 1~2 分钟，有实时日志）。
3. 点「生成推荐」：按分组紧张度出推荐表，可导出 CSV / 复制 Markdown 表格。
4. 「剧名定组」页签：粘贴剧名（回车/逗号/顿号分隔），生成定组表。

### 飞书接入检测（v1.1.0 新增）

设置 → 「飞书四表同步（可选）· 接入检测」填入自建应用 **App ID / Secret**，点
**「检测接入能力」**，工具会逐个资源只读探测（约 1~3 秒），明确输出：

- **可接入 / 不可接入**：覆盖每日剧单、YC 一周新剧、分销推广剧单、每日必做&推荐剧单四类核心资源，
  外加投放任务表（附加）；每张表独立结论，互不影响。
- **失败原因**：错误码映射成中文（如 `99991672` → 应用未开通 scope、`1254302` → 未加文档协作者），
  未收录的错误码原样透出，不猜。
- **缺失权限**：具体到 scope 名（如 `bitable:app:readonly`），并给出**一键申请权限**直达链接。
- **因权限/配置不足暂不能发布的项目**：单独列出，方便照单修复。
- 顶部状态条常驻「飞书 X/4」徽章；推荐表顶部会如实标注哪些源未参与加权。

修复动作速查：

| 报错 | 原因 | 怎么修 |
|---|---|---|
| `99991672` Access denied | 应用未开通 scope | 点「一键申请权限」开通 → **必须创建版本并发布**（管理员审核通过才生效） |
| `99991663` | Secret 错或未发布版本 | 重抄 Secret；版本管理与发布里创建版本 |
| `1254302` / `91403` | 应用不是文档协作者 | 打开该表 → 「…」→ 添加文档协作者 → 搜应用名 → 可阅读 |
| `131006` | 应用不在知识库空间 | 知识库设置 → 成员管理 → 添加应用 |
| `10014` | App ID 不存在 | 核对 `cli_` 开头的完整串 |

命令行自检：`BeidouReco.exe --feishu-selftest`，结果写 `feishu_report.json`（只测飞书，不拉 MCP，3 秒出结果）。

### 数据源

| 数据源 | 鉴权 | 说明 |
|---|---|---|
| 北斗 MCP（发布组 / 素材库 / 出单 / 剧目广场 / 主页数） | 你的 API Key | 核心数据 |
| 运营短剧看板（drama-dashboard.app.workbuddy.host） | 公开 | 昨日/今日出单、90 天剧排名 |
| 短剧上新监控面板 | 公开 | 11 平台近 7 天上新 |
| 飞书四表（每日剧单 / YC 新剧 / 分销剧单 / 必做表） | 可选 | 在设置里填飞书自建应用 App ID / Secret（只读权限即可）；不填则推荐自动退回 MCP+看板+监控三源 |

### 口径

- **类型**：一周内上线 = 新剧；推广人数 > 1000 = 热门；平台标注（sort_tag=recent_hot）= 爆款；其余 = 老剧。
  判定顺序：爆款 > 新剧 > 热门 > 老剧。
- **题材**（多选，11 类）：ABO/狼人、校园/体育、黑帮/犯罪、豪门/总裁、人外/奇幻、娱乐圈/竞技、
  穿越/系统/重生、现实向、女频、男频、男同。由内置剧目题材库 + 关键词规则判定。
- **归组**：题材对口优先；爆款/过千进热门；验证过（出单/过千）进潜力；长剧（≥55 集）进弃用组走量；
  男频/男同/系统/校园进养号；停用为隔离区不出推荐。
- **紧张度**：剩余集数 ÷ 主页数，越低越靠前；极缺（<4）/偏紧（<12）/充足。
- 已知限制：剧目广场的「上线时间/推广人数」可能因平台重新上架被重置（工具会在理由里提示）。

## 从源码构建

```bat
pip install -r requirements.txt
build.bat          :: 产物 dist\BeidouReco.exe
.\dist\BeidouReco.exe --selftest   :: 无界面自检（需先设置 BEIDOU_API_KEY 环境变量）
```

主要依赖：Python 3.10+，PyInstaller 打包，纯标准库 HTTP 服务（无需 Flask），前端无框架。

## 目录结构

```
app.py             入口：本地服务 + 设置/缓存/自检
core/mcp.py        北斗 MCP 客户端（JSON-RPC，429/504 退避）
core/genre.py      类型与题材判定
core/sources.py    看板 / 监控面板 / 飞书（可选，逐表状态）
core/feishu_check.py  飞书接入能力检测（分级探测 + 错误码字典 + 一键申请链接）
core/reco.py       推荐引擎（按组推荐 + 剧名定组）
web/               前端（原生 HTML/JS/CSS，暗色主题）
assets/            剧目题材库（genre_map / worldview_map）
```

## v1.1.3 更新（推荐按钮可重复使用）

- **修复「点击推荐后无法再次推荐」**：生成中若请求失败/超时/返回异常，按钮会永久卡在
  「生成中…」无法再点。现在所有请求都有：超时保护（推荐 120s／定组 180s／测试连接 30s）、
  非 JSON 响应明确报错、**try/finally 保证按钮在任何路径下都恢复可点**、防重入（禁用期
  重复点击直接忽略）。
- **拉取失败不再锁死推荐**：拉取失败但本机有缓存数据时，自动回退到缓存继续推荐并提示；
  确认弹窗改为「正在拉取数据，完成后即可生成推荐」的非阻塞提示，不再打断流程。
- 渲染失败单独捕获并提示，不再静默；「测试连接」「保存设置」同样加了异常兜底。
- 设置弹窗支持 Esc / 点击遮罩关闭，关闭时清空测试消息残留。

## v1.1.1 更新（版本状态修复）

- **版本号单一来源**：页面版本改为启动时从 `/api/health` 动态渲染，不再在 HTML 里硬编码，
  彻底避免「exe 是新版、页面显示旧版」的错位。
- **Key 绑定版本可追溯**：`config.json` 新增 `saved_by_version`，状态栏悬停可看到北斗 Key
  绑定于哪个版本；旧版（≤1.1.0）写入的配置会显示「已配置 …（旧版配置）」黄标，重新保存
  Key 即更新绑定版本（Key 本身仍有效，无需重填）。
- `/api/health` 现返回 `version`、`config_version`、`config_legacy`、`config_path`。
- 新增 `BeidouReco.exe --reset-state`：一键清空 `%APPDATA%\BeidouReco` 下的 config.json 与
  cache.json，用于干净验证或换 Key 重绑。
- 修复 Server 响应头版本硬编码（`BeidouReco/1.0` → 跟随实际 VERSION）。
